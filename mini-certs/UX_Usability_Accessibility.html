UX, Usability & Accessibility Certificate

Prerequisites: None

Final Goal: Students will evaluate and design software from the perspective of the people who actually use it — including people using assistive technology.

Learning Targets

  • Apply usability testing methods and heuristics to identify real problems in an interface
  • Practice UX/UI design — user research, personas, wireframing, and visual/interaction design principles
  • Explain and apply accessibility concepts, including WCAG, color contrast, screen-reader-friendly coding, ARIA roles, and accessibility testing tools

Proof

Each checkbox represents a proof of understanding. Students must demonstrate mastery through evaluation, creation, or application.

Usability Testing

  • Testing Methods – Describe at least 3 usability testing methods (think-aloud protocol, A/B testing, heuristic evaluation)
  • Usability Heuristics – List and explain Nielsen's 10 usability heuristics with real examples
  • Test Report – Conduct a simple usability test on a website and create a report identifying 5 usability issues
  • Other: ________________________________

UX/UI Design

  • UX vs. UI – Explain the difference between UX (user experience) and UI (user interface) design
  • User Personas – Create 2 user personas for a specific application with demographics, goals, and pain points
  • Wireframe Creation – Create wireframes for 3 key screens of an application using paper or digital tools
  • Design Principles – Apply design principles (consistency, hierarchy, feedback) to improve a poorly designed interface
  • Other: ________________________________

Accessibility

  • WCAG Definition – Define WCAG (Web Content Accessibility Guidelines) and explain its purpose and its levels (A, AA, AAA)
  • Color Contrast – Check the color contrast ratio of an existing page (or one you built) using a contrast checker, and fix any text/background pair that fails
  • Coding for Screen Readers – Write HTML that a screen reader can navigate meaningfully — semantic tags, alt text, and labeled form fields — and explain what a screen reader would announce for each
  • ARIA Roles – Define what an ARIA role is and add at least 2 appropriate ARIA attributes (e.g. role, aria-label) to a page, explaining what each one communicates to assistive technology
  • Accessibility Testing Tools – Find and run an accessibility checker (e.g., a browser extension like Buddy or WAVE) on a real page, and document what it flagged and how you'd fix it
  • Other: ________________________________
✅ Overall Mastery
Conducts usability tests and applies heuristics to find real problems, designs interfaces grounded in user research and design principles, and builds pages that are accessible by WCAG standards — checking color contrast, coding for screen readers, using ARIA roles correctly, and verifying work with a real accessibility testing tool.

Success Indicators

Students are ready to build on UX/usability/accessibility fundamentals when they can:

  • Spot a usability problem in an interface without being told to look for one
  • Explain a design decision in terms of the user's goals, not just how it looks
  • Run an accessibility check on their own work before calling it done, as a habit, not an afterthought
  • Explain to another student why a given page would or wouldn't work well with a screen reader

This UX, Usability & Accessibility Certificate treats accessibility as a core design skill, not an add-on — the same rigor applied to usability testing and interface design applies to making sure that design actually works for every user.
