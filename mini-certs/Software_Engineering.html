Software Engineering Certificate

Prerequisites: Software Development Concepts Certificate

Final Goal: Students will understand how real software systems are structured, built, and shipped — beyond writing a single program, toward how production systems are architected, versioned, and delivered.

Learning Targets

  • Compare monolithic, tiered, and microservices architectures and diagram how each structures a system
  • Apply design patterns (MVC, MVVM, component-based design) and explain when each fits, and represent class composition with UML
  • Identify cross-cutting concerns (security, logging, error handling) and strategies for handling them
  • Compare programming paradigms, define compiled and interpreted languages, and compare languages and technology stacks
  • Explain the purpose of a CI/CD pipeline and diagram its stages
  • Demonstrate version control methods and explain why they matter to a team

Proof

Each checkbox represents a proof of understanding. Students must demonstrate mastery through diagramming, comparison, or hands-on application.

Multi-Tiered & Distributed Design

  • Monolith Definition – Define monolithic architecture and give 2 real-world examples
  • 3-Tier Architecture – Define 3-tier architecture (presentation, business logic, data access) and diagram it
  • N-Tier Extension – Explain how 3-tier architecture extends to N-tier
  • Microservices – Define microservices architecture and diagram independent services communicating via APIs
  • Cloud Scalability – Explain how microservices leverage cloud infrastructure for scalability
  • Architecture Comparison (Composite) – Compare monolithic, tiered, and microservices architectures across scalability, complexity, and deployment, and recommend one for a given scenario

Design Patterns

  • MVC – Define Model-View-Controller (MVC) and diagram how it separates data, display, and logic
  • MVVM – Define Model-View-ViewModel (MVVM) and explain how it differs from MVC
  • Component-Based Design – Define the component-based design pattern (self-contained, reusable pieces)
  • Patterns in Practice (Composite) – Find three common frameworks and identify what design patterns they use
  • UML Composition – Draw a simple UML diagram showing how one class is composed of others

Cross-Cutting Concerns

  • Concern Identification – List and define at least 3 cross-cutting concerns (security, logging, error handling, etc.)
  • Impact Analysis – Explain how a cross-cutting concern affects multiple parts of a system rather than living in one place
  • Implementation Strategies – Research and explain 2 approaches to handling cross-cutting concerns (middleware, service layers, aspect-oriented patterns)

Programming Languages & Technology Stacks

  • Procedural Programming – Define procedural programming, with a code example
  • Object-Oriented Programming – Define object-oriented programming (OOP), with a code example
  • Functional Programming – Define functional programming, with a code example
  • Declarative Programming – Define declarative programming, with a code example
  • Hybrid Languages (Composite) – Identify a hybrid language that combines multiple paradigms, and explain which ones
  • Compiled Languages – Define a compiled language, with 2 examples
  • Interpreted Languages – Define an interpreted language, with 2 examples
  • Language Landscape – Identify at least 3 general-purpose programming languages and their typical use cases
  • SQL as a DSL – Explain SQL as an example of a domain-specific language (DSL)
  • Technology Stack – Explain the components of one named technology stack of your choice (e.g. LAMP, MEAN/MERN, a Java/Spring or .NET stack)

CI/CD

  • Continuous Integration – Define Continuous Integration (CI) and explain why teams automate it
  • Continuous Deployment – Define Continuous Deployment (CD) and explain why teams automate it
  • Pipeline Diagram (Composite) – Diagram a CI/CD pipeline showing code commit → build → automated test → deployment
  • Failure Scenario (Composite) – Explain what should happen to a deployment when an automated test in the pipeline fails, and why that matters

Version Control

  • Why It Matters – Explain what problems version control solves for a team (history, collaboration, recovery) vs. working without it
  • Commit – Demonstrate making a commit to a repository
  • Branch – Demonstrate creating and using a branch
  • Merge – Demonstrate merging a branch
  • Core Workflow (Composite) – Demonstrate a full commit → branch → merge workflow on a real repository
  • Conflict Resolution – Resolve a merge conflict between two branches and explain what caused it
✅ Overall Mastery
Compares software architectures and recommends one for a given scenario, applies design patterns (MVC, MVVM, component-based) and UML composition appropriately, identifies and explains cross-cutting concerns, compares languages/paradigms/technology stacks, explains and diagrams a CI/CD pipeline, and demonstrates real version-control workflows including conflict resolution.

Success Indicators

Students are ready for advanced software engineering study when they can:

  • Justify an architecture choice (monolith vs. tiered vs. microservices) for a specific project, not just define the terms
  • Recognize a cross-cutting concern in an unfamiliar codebase
  • Explain what a CI/CD pipeline would catch that manual testing alone might miss
  • Use version control as a normal part of their own workflow, not something reserved for group projects

This Software Engineering Certificate moves from "can I write a program" to "can I reason about how a real system is built, structured, and delivered" — the layer of practice above individual language skill.
