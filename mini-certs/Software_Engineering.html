Software Engineering Certificate

Prerequisites: Software Development Concepts Certificate

Final Goal: Students will understand how real software systems are structured, built, and shipped — beyond writing a single program, toward how production systems are architected, versioned, and delivered.

Learning Targets

  • Compare monolithic, tiered, and microservices architectures and diagram how each structures a system
  • Apply design patterns (MVC, MVVM, component-based design) and explain when each fits
  • Identify cross-cutting concerns (security, logging, error handling) and strategies for handling them
  • Compare programming languages, paradigms, and technology stacks, and explain compiled vs. interpreted execution
  • Explain the purpose of a CI/CD pipeline and diagram its stages
  • Demonstrate version control methods and explain why they matter to a team

Proof

Each checkbox represents a proof of understanding. Students must demonstrate mastery through diagramming, comparison, or hands-on application.

Multi-Tiered & Distributed Design

  • Monolith Definition – Define monolithic architecture and explain its "all-in-one" nature, with at least 2 real-world examples
  • 3-Tier / N-Tier Explanation – Define and diagram the presentation, business logic, and data access tiers, and explain how 3-tier extends to N-tier
  • Microservices & Cloud – Define microservices architecture, diagram independent services communicating via APIs, and explain how it leverages cloud infrastructure for scalability
  • Architecture Comparison – Compare monolithic, tiered, and microservices architectures across scalability, complexity, and deployment, and recommend one for a given project scenario

Design Patterns

  • MVC – Define Model-View-Controller and diagram how it separates an application's data, display, and logic
  • MVVM – Define Model-View-ViewModel and explain how it differs from MVC
  • Component-Based Design – Explain the component pattern (self-contained, reusable UI pieces) and identify the components in an existing application
  • Pattern Comparison – Compare MVC, MVVM, and component-based design, and explain when each is a good fit
  • Other: ________________________________

Cross-Cutting Concerns

  • Concern Identification – List and define at least 6 cross-cutting concerns (security, logging, error handling, etc.)
  • Impact Analysis – Explain how each concern affects multiple parts of a software system rather than living in one place
  • Implementation Strategies – Research and explain at least 2 approaches to handling cross-cutting concerns (middleware, service layers, aspect-oriented patterns)
  • Other: ________________________________

Programming Languages & Technology Stacks

  • Compiled vs. Interpreted – Compare compiled and interpreted languages with 3 examples of each and the performance implications
  • Paradigm Comparison – Explain procedural, OOP, functional, and declarative programming with code examples, and identify a hybrid language that combines multiple paradigms
  • Language Landscape – Identify at least 7 general-purpose languages and their typical use cases, plus SQL as an example of a domain-specific language
  • Technology Stacks – Explain the components of at least 3 named technology stacks (e.g., LAMP, MEAN/MERN, a Java/Spring or .NET stack) and compare their tradeoffs
  • Other: ________________________________

CI/CD

  • CI/CD Purpose – Explain what continuous integration and continuous delivery/deployment mean and why teams automate them
  • Pipeline Diagram – Diagram a CI/CD pipeline showing code commit → build → automated test → deployment
  • Failure Scenario – Explain what should happen to a deployment when an automated test in the pipeline fails, and why that matters
  • Other: ________________________________

Version Control

  • Core Workflow – Demonstrate a commit → branch → merge workflow on a real repository
  • Why It Matters – Explain what problems version control solves for a team (history, collaboration, recovery) versus working without it
  • Conflict Resolution – Resolve a merge conflict between two branches and explain what caused it

✅ Overall Mastery
Compares software architectures and recommends one for a given scenario, applies design patterns (MVC, MVVM, component-based) appropriately, identifies and explains cross-cutting concerns, compares languages/paradigms/technology stacks, explains and diagrams a CI/CD pipeline, and demonstrates real version-control workflows including conflict resolution.

Success Indicators

Students are ready for advanced software engineering study when they can:

  • Justify an architecture choice (monolith vs. tiered vs. microservices) for a specific project, not just define the terms
  • Recognize a cross-cutting concern in an unfamiliar codebase
  • Explain what a CI/CD pipeline would catch that manual testing alone might miss
  • Use version control as a normal part of their own workflow, not something reserved for group projects

This Software Engineering Certificate moves from "can I write a program" to "can I reason about how a real system is built, structured, and delivered" — the layer of practice above individual language skill.
