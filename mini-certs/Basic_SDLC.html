Software Development Concepts Certificate

Prerequisites: None

Final Goal: Students will understand why software projects are organized into a life cycle, compare the major methodologies used to run that life cycle, and understand how a project's major roles fit into its phases and what each one actually produces.

Learning Targets

  • Define the Software Development Life Cycle (SDLC) and explain why software projects are divided into phases
  • Compare the Agile, Waterfall, and iterative approaches to running that life cycle
  • Identify the major roles on a software project team, which SDLC phase(s) each works in most, and the main artifacts each one produces

Proof

Each checkbox represents a proof of understanding. Students must demonstrate mastery through explanation, diagramming, or application.

Job Roles in the SDLC

For each role: which SDLC phase(s) it works in most, and the main artifacts it produces.

Business Owner/Sponsor

Phase: Initiation/Planning  ·  Main artifacts: vision statement, budget approval, prioritization decisions

  • Phase Placement – Explain why the business owner/sponsor is most active at the very start of a project, and what happens if that role is skipped
  • Artifact Creation – Draft a short vision statement and a prioritization decision (what gets built first, and why) for a sample project
  • Other: ________________________________

Business Analyst

Phase: Requirements/Analysis  ·  Main artifacts: requirements document, user stories

  • Phase Placement – Explain how the business analyst bridges the business owner's goals and the technical team's implementation
  • Artifact Creation – Write 5 user stories in the "As a [role], I want [feature] so that [benefit]" format, and a short requirements document for one feature
  • Other: ________________________________

Usability Tester

Phase: Design & Testing (user-facing verification)  ·  Main artifacts: usability test reports, heuristic evaluation findings

  • Phase Placement – Explain why usability testing happens throughout design and again before launch, not just once at the very end
  • Artifact Creation – Conduct a simple usability test on an existing page and write up a usability test report identifying the issues found
  • Other: ________________________________

The actual usability-testing methods and heuristics are practiced in the UX, Usability & Accessibility Certificate — this entry covers the role's place in the SDLC, not the skill itself.

UX/UI Designer

Phase: Design  ·  Main artifacts: wireframes, personas, prototypes

  • Phase Placement – Explain what a UX/UI designer needs from the business analyst's requirements before design work can start
  • Artifact Creation – Create a wireframe and a persona for one screen of an application
  • Other: ________________________________

The actual UX/UI design methods (personas, wireframing technique, design principles) are practiced in the UX, Usability & Accessibility Certificate — this entry covers the role's place in the SDLC, not the skill itself.

Technical Architect

Phase: Design  ·  Main artifacts: architecture diagram, technical design document, technology choices

  • Phase Placement – Explain why architectural decisions happen before implementation begins, and what it costs to change them later
  • Artifact Creation – Create a high-level architecture diagram for a web application, and justify one technology choice against the project's requirements
  • Other: ________________________________

Front End Developer

Phase: Implementation (client-side)  ·  Main artifacts: HTML/CSS/JS code, UI components

  • Phase Placement – Explain what a front end developer needs from the design phase before implementation can start
  • Artifact Creation – Convert a design mockup into working HTML/CSS/JS, with browser testing across at least 2 browsers
  • Other: ________________________________

Back End Developer

Phase: Implementation (server-side)  ·  Main artifacts: APIs, server logic, database integration

  • Phase Placement – Explain what a back end developer needs from the architecture phase before implementation can start
  • Artifact Creation – Design and document a simple REST API, including basic CRUD operations against a database
  • Other: ________________________________

Full Stack Developer

Phase: Implementation (end-to-end)  ·  Main artifacts: complete features spanning client and server

  • Phase Placement – Explain why a full stack developer's work spans both the front-end and back-end phases of implementation
  • Artifact Creation – Build a small application with front-end and back-end components that communicate correctly, and document the development workflow you followed
  • Other: ________________________________

Database Developer

Phase: Design + Implementation (data layer)  ·  Main artifacts: ER diagrams, schema, queries

  • Phase Placement – Explain why data modeling typically happens alongside architectural design, before most implementation starts
  • Artifact Creation – Create an ER diagram for a business domain, then write the SQL to create the matching tables and constraints
  • Other: ________________________________

Mobile Developer (iOS/Android)

Phase: Implementation (mobile platforms)  ·  Main artifacts: platform-specific app builds

  • Phase Placement – Explain how platform choice (native vs. cross-platform) is a design decision that shapes the whole implementation phase
  • Artifact Creation – Address at least 3 mobile-specific constraints (screen size, touch input, connectivity) in a design or prototype for a mobile feature
  • Other: ________________________________

QA Tester / Automation Tester

Phase: Testing/Verification  ·  Main artifacts: test cases, bug reports, automated test suites

  • Phase Placement – Explain why testing happens continuously alongside implementation rather than only at the very end
  • Artifact Creation – Write detailed test cases for a feature (preconditions, steps, expected results), execute them, and file a bug report for anything that fails
  • Other: ________________________________

DevOps Engineer

Phase: Deployment/Maintenance  ·  Main artifacts: deployment pipeline, monitoring/logging setup

  • Phase Placement – Explain why DevOps work spans the boundary between "finished implementation" and "running in production"
  • Artifact Creation – Diagram a deployment pipeline showing build → test → deploy stages, and describe what should be monitored once it's live
  • Other: ________________________________
✅ Overall Mastery
Defines SDLC and explains why software work is divided into phases, compares Agile/Waterfall/iterative approaches and picks the right one for a scenario, and — for each major project role — identifies which phase it works in most and produces the artifact that role is actually responsible for.

Success Indicators

Students are ready to build on SDLC fundamentals when they can:

  • Explain, for an unfamiliar project scenario, which methodology fits best and why
  • Look at an artifact (a vision statement, an ER diagram, a test case) and correctly identify which role produced it and which phase it belongs to
  • Explain what goes wrong on a project when a phase gets skipped or a role's artifact never gets produced
